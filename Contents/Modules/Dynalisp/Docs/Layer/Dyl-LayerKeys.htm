Layer Keys

Function Syntax DYL-LAYERKEYS
Source File Modules\Dynalisp\Apps\Layer\Dyl-LayerKeys.lsp (command) and Modules\Dynalisp\Remote\Dyl-LayerKey.lsp (layer keys, loaded at startup)
Requires AutoCAD for Windows (ActiveX / Visual LISP)
Licence GNU General Public License v3

Program Description

Dynalisp layer keys work like the AutoCAD Architecture layer keys, but in any AutoCAD. A layer key is a short name, such as THIN or HATCH, that an App uses instead of a layer name. Each key gives the layer to use and the properties to create that layer with when the drawing does not have it yet. Changing the layer of a key changes where every App that uses the key draws, without editing the Apps.

The keys are saved to Modules\Dynalisp\Res\LayerKeys.csv. DYL-LAYERKEYS opens the Layer Keys dialog to create and edit them. The same dialog opens from the Edit layer keys... button of the Materials dialog (Quick Draw).

Layer Keys Dialog

  • Layer key list – key, layer and status (blank = default values, modified = edited default key, custom = key created by the user).
  • Key – the name used by the Apps (upper case). The name of a default key cannot be changed.
  • Layer name, Description, Color, Linetype, Lineweight, Plot – the layer and the properties it is created with. Click the color swatch to pick a color in the AutoCAD color dialog. The linetype is picked from the .lin files of the support path and the linetypes already in the drawing.
  • Phased – while auto-phase is on, the key gives its layer in the active phase of the drawing (see Layer Phase): A-Detl-Thin-E in existing, A-Detl-Thin-N in new work, A-Detl-Thin when auto-phase is off or the drawing has no active phase. Phased keys are listed as Layer-[phase].
  • Under the values, the dialog says whether the layer already exists in the current drawing (used as is) or will be created when a key is used.
  • New – adds a custom key. Copy – adds a custom key with the values of the selected one. Delete – removes the selected custom key (the layer itself is not deleted).
  • Reset key – restores the default values of the selected default key. Restore defaults – restores every default key; custom keys are kept.
  • OK saves LayerKeys.csv, Cancel discards every change. Open Docs opens this page.

How It Works

  1. When an App uses a key, the key is looked up in LayerKeys.csv. Default keys missing from the file use their default values.
  2. If the layer of the key exists in the drawing, it is used as is: its properties are never changed.
  3. If it does not exist, it is created with the color, linetype, lineweight, plot setting and description of the key. A linetype that is not loaded yet is loaded from acad.lin (imperial) or acadiso.lin (metric); if it cannot be loaded, the layer stays Continuous.
  4. While auto-phase is on, a phased key adds the active phase to its layer name; that layer is created with the phase color (2# for existing to demolish, 20# for existing to remain, the key color otherwise). With auto-phase on, objects created on the layer of a phased key also go to the active phase.
  5. A key that is not defined uses a layer of the same name, created as color 7, Continuous, default lineweight; a message names the key on the command line.

Using Layer Keys In An App

  • (Remote>>Dyl:LayerKeyLayer "THIN") – returns the layer of the key, created if missing.
  • (Remote>>Dyl:LayerKeyApply (entlast) "THIN") – puts an object on the layer of the key.
  • (Remote>>Dyl:LayerKeyRead) – returns every key: (key layer color linetype lineweight plot description phased).
  • (Remote>>Dyl:LayerKeyDialog key) – opens the Layer Keys dialog on a key; returns T when the keys were saved.

Known Limitations

  • Colors are AutoCAD Color Index values (1–255); true colors and color books are not supported.
  • Editing a key does not update layers already created in drawings.
  • LayerKeys.csv cannot be saved while it is open in Excel: an alert is shown and the changes are lost.

Command Names And Aliases

Each program has one main command starting with Dyl-. The short names are its aliases: they run the same command, and can be added, renamed or removed in Dyl-Suite (saved in Resources\Aliases.csv).
